# [ 해킹툴 리뷰 ] thewhiteh4t - seeker

이번에 알아볼 해킹툴은 seeker이다.

이름에서 알 수 있듯이 접속된 기기의 위치를 따주는 툴이다.

우선 내 메인 노트북으 kali 이기 때문에 진행하기 훨씬 편했다.

해킹툴의 깃허브 주소는 밑과 같다.

[https://github.com/thewhiteh4t/seeker](https://github.com/thewhiteh4t/seeker)

사이트에 들어가게 되면 이런 창이 뜨게 된다.

![image01](/assets/uploads/mwbtnumc.png)

깃허브를 써본 사람이라면 알겠지만 다운로드 방식이 여러 개가 있지만 나는 그냥 terminal에 clone 했다.

![image02](/assets/uploads/mwbto2n0.png)

들어가서 폴더를 확인해보니 여러 파일들이 존재한다.

![image03](/assets/uploads/mwbtokbz.png)

![image04](/assets/uploads/mwbtopku.png)

뭐 실행까지 하긴 했는데 저번에 실행 했을 땐 서버가 제대로 구동하지 않았던 거 같아서 마저 진행해보고 안되면 차선책으로 서버를 열어보겠다.

![image05](/assets/uploads/mwbtovtu.png)

흠.. 이젠 서버 자체를 툴에서 뺀 거 같아서 다른 터미널에서 ngrok으로 서버를 열어야겠다.

ngrok이란? 여러 용도로 사용할 수 있겠지만 로컬 서버를 다른 사람들도 접속할 수 있는 서버로 열어준다.

용량이 작은 무료 호스팅 정도로 사용하면 좋을 것 같다.

ngrok 사이트는 밑과 같다. (QR 인증도 해야하고 회원가입도 해야하기에 은근히 번거롭다 ㅇㅇ)

[https://dashboard.ngrok.com/](https://dashboard.ngrok.com/)

회원가입을 완료하고 간단한 질의에 대답하면 이런 화면이 나올 것이다.

![image06](/assets/uploads/mwbtp77z.png)

이제 ngrok을 설치하고 인증키(Free Plan)을 입력하면 준비는 완료된다.

설치 방법은 밑을 참고하세연

```bash
curl -sSL https://ngrok-agent.s3.amazonaws.com/ngrok.asc \
  | sudo tee /etc/apt/trusted.gpg.d/ngrok.asc >/dev/null \
  && echo "deb https://ngrok-agent.s3.amazonaws.com bookworm main" \
  | sudo tee /etc/apt/sources.list.d/ngrok.list \
  && sudo apt update \
  && sudo apt install ngrok
```

```bash
ngrok config add-authtoken "사용자의 개인키"
```

```bash
ngrok http 80
```

마지막 ngrok http 80은 잘 되는지 테스트 하는 명령어이다. 

ngrok을 이용해서 http 프로토콜로 80번 포트로 서버를 열겠다는 뜻이다.

안타깝게 무료 플랜은 도메인을 지정할 수 없고 랜덤으로 나오지만 뭐 테스트 하기에는 충분하다.

![image07](/assets/uploads/mwbtpdzd.png)

테스트까지 잘 되는 것을 확인했으니 이제 해킹툴을 실행해보자.

![image08](/assets/uploads/mwbtpqkh.png)

이렇게 두 개의 터미널로 하나는 seeker를 실행하고 하나는 ngrok을 실행하면 된다.

ngrok 터미널에 임의의 사이트가 하나 있는데 그 사이트로 접속하면 우리가 로컬로 포워딩한 사이트가 열릴 것이다.

![image09](/assets/uploads/mwbtpxst.png)

이렇게 미리 seeker에서 만들어둔 사이트로 이동하게 되고 여기서 위치 권한을 허용한다는 버튼을 클릭하면 seeker 터미널로 위치 정보가 나오게 된다. 

위치 정보 뿐만 아니라 아이피나 접속 환경 등 여러가지가 나온다.

![image10](/assets/uploads/mwbtq2wd.png)

필자는 현재 핫스팟으로 연결했기에 정확한 위치나 아이피가 나오지는 않지만 공유기를 사용하여 접속한 사용자들은 위치를 노출하게 되는 원리이다.

정리하면, seeker에서 미리 만들어둔 위치 추적 양식이 있고 로컬에서 포워딩한다.

ngrok을 통해서 서버를 열고 사용자들이 접속하여 위치 정보를 허용하면 seeker에서 추적해서 알려준다.

꽤 간단하지만 어떻게 사람들을 교묘하게 속이느냐에 따라 악용이 가능해 보인다.

권한 허용/거부를 물어보면 꼭 다시 한 번 확인하고 허용하도록 하자.
